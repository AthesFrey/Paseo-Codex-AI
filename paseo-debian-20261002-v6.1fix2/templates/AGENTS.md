# 项目执行约定

用户要求实施项目工作时，先识别已有项目、manifest 和 lockfile，然后直接完成实现、必要的依赖安装、构建和验证。纯聊天、解释、研究和知识整理不创建项目文件，也不初始化 Git 仓库。保持执行路径短，只运行与当前改动有关的检查，不为了形式增加重复扫描或无关构建。

工作区根目录是 `/srv/proj`；用户未指定位置的新项目创建在 `/srv/proj/<项目名>`，不要直接把工作区根目录初始化成项目。同一项目的修复、迭代、升级、重构和改名继续使用原目录。任务 worktree 位于 `/srv/paseo/worktrees`。现有仓库先执行 `git status --short`，保留用户未提交改动。较大的独立任务按需使用 `codex/<任务名>` 分支或 worktree；普通任务不需要创建分支。

文件保持就近、可预测和可清理：源代码、配置和文档放在项目规定的位置；构建产物只放项目已有的 `build/`、`dist/` 等目录；依赖目录使用项目既有约定。缓存、下载物、解压目录、测试 stub、临时日志、临时归档和 Python 字节码只能放在 `/srv/paseo/cache/<项目名>/` 或 `/srv/paseo/tools/`，不得在 `/srv/proj` 或项目根创建隐藏临时目录。临时目录用唯一任务名，任务结束后删除；需要交付的生成文件才保留在项目中。尊重现有 `TMPDIR`、`UV_*` 等变量。

允许按项目需要自动安装、运行项目局部依赖和开发工具，无须为已授权的普通依赖逐次询问。

- Python：优先 `uv sync`/`uv add` 或项目已有 `.venv`；兼容新 Python 版本时使用 `uv python install`，安装目录由环境变量提供。
- Node：遵守已有 npm/pnpm/yarn 锁文件，不随意更换包管理器；项目依赖放 `node_modules`。缺少用户级开发工具时可装入 `/srv/paseo/tools`，保持项目版本可追踪。
- 依赖构建失败先阅读真实错误；不要全局 `sudo pip`，不修改系统 Python、不安装 Docker daemon、不请求 Docker socket。
- apt/系统包需要管理员安装；遇缺失开发头文件或系统库时说明确切包名与原因。不得修改 sudoers、防火墙、系统服务或 `/etc`。

需要 Git 时遵守以下规则：代码项目才使用 Git，日常对话和普通目录项目不运行 `git init`；已有仓库先检查状态，绝不覆盖、清理或重置用户改动。只把本次任务相关文件加入暂存区，避免提交密钥、缓存、依赖目录、临时产物和完整环境文件；必要时补充项目 `.gitignore`。独立改动使用 `codex/<任务名>` 分支或 worktree，完成后检查 `git diff` 和 `git status`。不自动 commit、merge、push、tag 或部署，除非用户明确要求；不使用强制推送或破坏性 Git 命令。Paseo worktree 仅用于 Git 项目，并放在 `/srv/paseo/worktrees`。

测试安装脚本、服务或部署流程时，不得直接修改真实 `/srv/paseo`、`/etc`、`/var`、systemd 或项目目录。使用 `/srv/paseo/cache/<项目名>/` 下的隔离目录、命令 stub 或静态检查；若脚本写死生产路径，先复制到隔离测试副本并重定向路径。测试结束前清理临时目录，并检查项目根没有新增的隐藏文件或无关产物。

仅运行必要检查，记录依赖文件变化和实际测试结果；不要声称未执行的测试已通过。不得打印 API key、环境变量全集、认证文件、密码或配对链接；用户要求分享日志时仅给相关片段。
